<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser->shared input contract | Browser code can construct payloads, but TypeScript shapes do not prove runtime validity. |
| browser->Socket.IO server | `client:game-input` crosses from untrusted browser to authoritative runtime. |
| server result->web results | Server-owned result details become displayed user-facing summary fields. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | `StraightObstacleInput.steerX` | mitigate | Shared input exposes only `steerX`; server plans must clamp finite numbers to `-1..1` and reject wrong mode/kind. |
| T-03-02 | Tampering | `GameInputPayload`, `StraightObstacleInput` | mitigate | Input type contains no speed, distance, hit count, slowdown, finish, ranking, or result fields; snapshot/results types are server-owned. |
| T-03-03 | Denial of Service | `StraightObstacleInput.sequence` | transfer | Runtime plan stores latest valid steering intent and ignores stale/non-finite sequence values; shared type includes the field needed for that mitigation. |
| T-03-04 | Information Disclosure / Accessibility | `StraightObstacleSnapshot.warning` | transfer | Web HUD plans render warning/slowdown/hit text with `aria-live`; shared snapshot exposes inspectable text state. |
</threat_model>
