## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline separators, compact metadata gaps, result summary key/value gaps |
| sm | 8px | Button group gaps, card internal rows, status pill spacing |
| md | 16px | Default lobby/result card padding, race option row gap, form field gap |
| lg | 24px | Panel section gap, lobby grid gap, results ranking-to-summary gap |
| xl | 32px | Page-level vertical spacing inside normal app chrome |
| 2xl | 48px | Major separation between lobby groups on desktop only |
| 3xl | 64px | Reserved for non-mobile page breaks outside Phase 6 core flows |

Exceptions: borders may remain 2px, 3px, or 4px to match existing arcade CSS. Buttons and compact catalog cards must keep touch targets at least 44px high on phones. Fullscreen race routes continue to use Phase 1 safe-area and viewport exceptions: CSS `env(safe-area-inset-*)`, `100dvh`, `100vw`, and fixed gameplay control dimensions.

## Typography

Allowed sizes and weights for Phase 6 lobby/results UI:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 12px | 400 | 1.3 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.1 |

Rules:
- Use exactly these four sizes for Phase 6 additions.
- Race catalog objective/control/skill copy uses Body at 16px on phones, not the existing 0.54rem/0.58rem lobby metadata size.
- Card labels, tags, and "Control" or "Skill" captions use Label at 12px.
- Heading is for section titles and race option names.
- Display is reserved for the page title only; do not use display type inside race cards, buttons, or result rows.
- Letter spacing is `0` for new mobile-readable body, labels, and button text. Existing brand/title letter spacing may remain outside the new Phase 6 additions.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0a0a12` | App background, empty page regions, lobby/results base |
| Secondary (30%) | `#0f0f1e` | Panels, race catalog cards, results summary surfaces, non-selected controls |
| Accent (10%) | `#ffd700` | Selected race option, primary CTA, winner/rank highlight, focus ring, one key metric per result summary |
| Destructive | `#ff3333` | Errors, unavailable/blocked states, kick/leave risk styling only |

Accent reserved for: selected game/race card border, selected card heading, primary CTA `Avvia Sessione`, first-place rank marker, one mode-critical result metric, and keyboard focus ring. Do not apply accent to every card border, every metadata label, all buttons, or decorative background glows.

Additional existing colors may be retained with constrained meanings: `#00aadd` for secondary telemetry labels, `#33ff66` for ready/available/live state, `#ddeeff` for primary text, and `#66798f` for subdued metadata that is not required for play decisions.

## Phase Interaction Contract

### Lobby Race Catalog

- Render the race catalog as compact selectable cards or rows, not as a second row of bare buttons.
- Each race option must expose exactly: label, objective, control, and skill focus.
- Race option order is fixed: Drag Gear, Straight Obstacle, Circle Track, Figure-Eight Track.
- On phones, race options stack in one column with the full option visible without horizontal scrolling.
- On wider screens, race options may use a two-column grid, but each card keeps the same internal information order.
- Selected state must be visible through border/background and text treatment, not color alone.
- Disabled/unavailable startability state must keep the card readable and explain the blocker through existing lobby error/status placement, not hidden hover-only text.
- Selecting Semaforo or Rigori must remain a first-level game choice alongside Corse/Race; Phase 6 must not bury non-race games under the race catalog.
- The active race selection must map one-to-one to the canonical shared variant id used by server registry, session routing, HUD mode, and results.

### Lobby Controls

- Primary flow remains: join/create lobby, choose game, choose race variant if race is active, ready, then host taps `Avvia Sessione`.
- `Avvia Sessione` remains disabled until all existing readiness and startability rules pass.
- The disabled start button must not be the only indication of a selection problem; preserve or add concise status/error text for blocked starts.
- Button labels remain short enough for 320px-wide phones and must not overflow their containers.
- Minimum tap target for all new catalog and action controls is 44px high.
- Keyboard focus order: game choices, race choices when visible, invite action, roster actions, ready/leave/start actions.
- Focus ring uses `#ffd700` and must be visible on cards, buttons, inputs, and links.

### Results Page

- Keep the shared rankings list as the primary results structure.
- Add mode-specific summaries after the ranking identity/time area or as a compact child block inside each ranking row.
- Results must degrade gracefully for older `RaceFinishedPayload` or partial `SessionFinishedPayload` values: rankings still render, summary helper returns nothing when required fields are absent.
- Results rows must use stable responsive layout: one column on small phones, ranking/name/score/summary grid on wider screens.
- First place may use the accent color once; lower ranks should remain secondary surfaces.
- Host post-game actions remain unchanged: `Rigioca`, `Torna alla Lobby`, and `Cambia Gioco`.
- Non-host post-game copy remains concise: waiting for host decision.

### Fullscreen Gameplay Regression

- Phase 6 must preserve the route property that race gameplay screens render outside `AppLayout`, topbar, `.viewport`, `.panel`, and card chrome.
- Starting each race variant from lobby must open the correct fullscreen screen or mode-aware fullscreen adapter.
- Do not reintroduce normal page scrolling into gameplay routes.
- Manual mobile viewport verification is required before completion at a 320px-wide phone viewport and at a landscape phone viewport.
- Manual verification must check: race catalog readability, no text overflow in action buttons/cards, correct route after starting each race mode, results summaries, and unchanged Semaforo/Rigori startability.

### Accessibility

- Race cards are buttons or radio-like controls with programmatic selected state (`aria-pressed` or equivalent).
- Each race card's accessible name includes the mode label; objective/control/skill text must be visible text, not only `aria-label`.
- Results summaries use text nodes, not canvas-only or visual-only badges.
- Lobby error messages use an alert/status region consistent with existing page patterns.
- Do not add hover-only explanations; all required phone lobby copy is always visible.
