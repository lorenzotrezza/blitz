<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| route->app layout | Gameplay route chooses whether normal chrome can consume viewport and scroll space. |
| controls->socket | User controls become untrusted `client:game-input` packets. |
| server snapshot->route | Authoritative server state becomes visual canvas and React HUD. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T1-01 | Tampering | `useLiveRaceSocket.submitInput` and future server runtimes | transfer | This plan emits typed race intent only; server runtime discriminant checks and numeric clamping are implemented in later per-mode phases when those runtimes consume `RaceGameInput`. |
| T1-02 | Denial of Service / Tampering | `SprintCircuitPage` integrated controls | mitigate | Use `useGameControls` reset lifecycle and reset on finish/unmount; route tests and control tests cover cancellation paths from Plan 02. |
| T1-03 | Information Disclosure / Accessibility | `SprintCircuitPage` HUD | mitigate | Convert snapshots into `RaceShellSnapshot` and render critical status through `GameHud` React text, not canvas-only pixels. |
| T1-04 | Tampering | `SprintCircuitPage`, `useLiveRaceSocket` | mitigate | Emit only `RaceGameInput` intent via `client:game-input`; preserve server snapshots/results as the only source for progress, finish, ranking, and result navigation. |
</threat_model>
