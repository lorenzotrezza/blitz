# Phase 1 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none - custom CSS in `apps/web/src/styles.css`; shadcn gate executed, `components.json` absent, non-interactive path recorded as no init |
| Preset | not applicable |
| Component library | none |
| Icon library | none; use text labels and simple glyphs already present in the app only when they improve control recognition |
| Font | `Press Start 2P`, monospace for arcade labels; game-critical HUD values must use the sizes below and must not use existing tiny body sizes |

Source notes: existing app uses a custom arcade CSS theme, React/Vite, no Tailwind config, no shadcn config, and no local project skills. This phase must reuse the custom CSS direction while creating a distinct fullscreen gameplay route instead of another card/panel page.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Hairline gaps inside HUD chips, analog vector/knob offsets |
| sm | 8px | Compact element spacing, HUD chip inner gaps |
| md | 16px | Default control/HUD spacing, safe gap between canvas and overlays |
| lg | 24px | Edge padding for landscape shell and control clusters |
| xl | 32px | Gap between left analog zone and right action zone when controls stack |
| 2xl | 48px | Major separation between HUD groups and non-overlapping canvas regions |
| 3xl | 64px | Page-level fallback spacing only outside active fullscreen gameplay |

Exceptions: CSS `env(safe-area-inset-*)`, `100dvh`, `100vw`, and canvas aspect sizing are allowed because the shell must respect phone browser chrome and OS gesture areas. Gameplay touch targets must be fixed multiples of 4: analog pad 144px minimum in landscape, 128px minimum in portrait, action buttons 72px minimum, keyboard-focus target 56px minimum. Do not use sub-4px spacing except 1px/2px borders already established by the app.

## Typography

Allowed sizes and weights for Phase 1 gameplay UI:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 12px | 400 | 1.3 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.1 |

Rules:
- Use exactly these four sizes in the fullscreen game shell, controls, HUD, empty state, and error state.
- Existing sub-12px pixel-font styles are not allowed for gameplay-critical status, control labels, errors, speed, progress, countdown, or penalty text.
- Letter spacing is `0` for all gameplay HUD and control text. Existing wider brand letter spacing stays outside the fullscreen route only.
- Display text is reserved for countdown, finish state, or the single most important metric. Do not use display sizing inside compact control buttons.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#06060d` | Fullscreen game background, canvas backing field, non-interactive empty regions |
| Secondary (30%) | `#0f0f1e` | HUD plates, control wells, compact status strips, non-card overlay surfaces |
| Accent (10%) | `#ffd700` | Primary action button active state, active analog vector/knob, countdown ready/go value, one mode-critical HUD value, focus ring |
| Destructive | `#ff3333` | Connection errors, penalty warnings, blocked/unavailable control state, destructive confirmations if later added |

Accent reserved for: primary action button active state, analog active vector/knob, countdown/go indicator, one mode-critical HUD metric, and keyboard focus ring. Do not apply accent to every button, all borders, all labels, or decorative backgrounds.

Additional existing colors may be retained only for limited meanings: `#00aadd` for secondary telemetry such as labels or track guide lines, `#33ff66` for positive live/ready state, and `#ddeeff` for readable primary text. The shell must not become a card-heavy dark dashboard; canvas/track visuals should provide the main visual mass.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Enter Race Shell |
| Empty state heading | Waiting for race |
| Empty state body | No live snapshot yet. Keep this screen open; the countdown appears when the server starts the session. |
| Error state | Connection lost. Rejoin from the lobby or refresh this session. |
| Destructive confirmation | None in Phase 1. Do not add destructive gameplay-shell actions. |

Copy rules:
- Active play HUD copy must be terse: objective, speed/progress, penalty/status, and one mode-critical metric only.
- Do not show instructional paragraphs inside the active gameplay viewport.
- Use mode labels that can evolve later: `Drag`, `Dodge`, `Circle`, `Figure Eight`, and keep detailed rules out of Phase 1.
- Error copy must pair a plain problem with one next action.

## Phase Interaction Contract

### Fullscreen Shell

- Render race sessions in a dedicated fullscreen gameplay route, not inside `.panel`, `.viewport`, `.card`, or the normal top navigation chrome.
- Shell dimensions: `width: 100vw`, `min-height: 100dvh`, `overflow: hidden`, `position: fixed` or equivalent route-level containment.
- Respect safe areas on all edges using `padding: max(16px, env(safe-area-inset-*));` with larger bottom padding around controls when needed.
- Default orientation target is landscape phone. Portrait must remain usable by stacking HUD top, canvas middle, and controls bottom without page scrolling.
- Canvas/track is the primary visual surface and must occupy the center of the viewport. HUD and controls overlay or dock around it without pushing the track below the fold.
- Normal app background glow, scanlines, topbar, card grids, and page-level panels must be hidden or excluded while in active gameplay.

### Control Primitives

- `AnalogPad`: bottom-left default zone, 144px minimum in landscape, 128px minimum in portrait, outputs normalized `{ x, y, magnitude }` continuously with `x` and `y` clamped to `-1..1` and `magnitude` clamped to `0..1`.
- `PrimaryActionButton`: bottom-right default zone, 72px minimum target, mode label supplied by caller. Phase 1 default label is `GO`.
- `SecondaryActionButton`: adjacent to primary action but visually lower priority, 72px minimum target, mode label supplied by caller. Phase 1 default label is `BRAKE`.
- Controls use Pointer Events with pointer capture where supported and set `touch-action: none`, `user-select: none`, and `-webkit-user-select: none` on control surfaces.
- Touch/mouse release, pointer cancel, blur, visibility change, and route unmount must reset active input to neutral.
- Visual feedback is required for pressed, dragged, disabled, and keyboard-focused states. Feedback must not change layout dimensions.

### Keyboard And Desktop Fallback

- Direction/analog fallback: WASD and Arrow keys map to the same normalized analog vector.
- Primary action fallback: Space and Enter.
- Secondary action fallback: Shift and Control.
- Mouse drag on the analog pad is supported for local testing.
- Keyboard focus order: analog zone, primary action, secondary action, exit/back control if present. Focus ring uses `#ffd700` and remains visible over dark surfaces.

### HUD Contract

- HUD is React-rendered text outside the canvas so tests and assistive tech can inspect state.
- HUD position: top edge in landscape; top plus side rail is allowed on wide screens. HUD must not overlap bottom controls.
- Required common fields: mode objective, speed or progress, penalty/status, current input state, session/countdown state.
- Mode-critical field slot: RPM/gear/shift window for drag, obstacle hit/slowdown for dodge, lap/checkpoint/direction for analog tracks.
- Use an `aria-live="polite"` region for countdown, status changes, penalties, and finish state. Do not spam every tick into live text.

### Shared Contract Expectations

- Shared input foundations belong in `packages/shared/src/game.ts` or adjacent shared exports, not local-only component state.
- Inputs must be discriminated by input kind or control mode. Minimum concepts: analog vector, button pressed/released state, action event, sequence/tick, and client timestamp.
- Snapshot foundations must support the common shell: `sessionId`, `modeId`, `status`, `countdown`, `players`, `progress`, `speed`, common HUD fields, and a mode-specific detail payload.
- Phase 1 must avoid finalizing detailed drag physics, obstacle layouts, checkpoint geometry, or per-mode scoring fields. Those belong to Phases 2-5.

## Component Inventory

| Component | Contract |
|-----------|----------|
| `FullscreenGameShell` | Owns viewport containment, safe-area padding, chrome hiding, landscape/portrait layout, and no-scroll behavior |
| `GameViewport` | Hosts canvas/track content with stable aspect ratio and no layout shift when snapshots arrive |
| `GameHud` | React text HUD with common fields, mode-critical slot, and live-region status |
| `AnalogPad` | Reusable pointer/touch/mouse analog primitive with normalized vector output |
| `ActionButton` | Reusable fixed-size button primitive for primary and secondary actions |
| `useGameControls` or equivalent hook | Normalizes pointer, keyboard, blur/cancel, and input reset behavior before socket emission |
| `GameEmptyState` | Uses copy from the copywriting contract while waiting for session snapshot/countdown |
| `GameErrorState` | Uses copy from the copywriting contract for lost session/socket state |
