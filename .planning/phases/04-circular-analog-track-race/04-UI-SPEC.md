## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gate label offsets, HUD chip inner gaps, analog knob/vector offsets |
| sm | 8px | Compact HUD spacing, checkpoint/status chip gaps |
| md | 16px | Default shell padding, canvas overlay gaps, safe separation between HUD and track |
| lg | 24px | Landscape edge padding and control cluster margins |
| xl | 32px | Gap between analog pad zone and any right-side secondary control/status zone |
| 2xl | 48px | Reserved space between bottom controls and readable track boundaries |
| 3xl | 64px | Page-level fallback spacing only outside active fullscreen gameplay |

Exceptions: CSS `env(safe-area-inset-*)`, `100dvh`, `100vw`, and canvas aspect sizing are allowed. Active gameplay touch targets must remain fixed multiples of 4: analog pad 144px minimum in landscape and 128px minimum in portrait; any optional action/reset button is 72px minimum; keyboard-focus targets are 56px minimum. Track geometry may use fractional canvas coordinates internally, but CSS layout spacing must use the scale above.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 12px | 400 | 1.3 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.1 |

Rules:
- Use exactly these four sizes in the fullscreen circle track route, HUD, controls, waiting state, error state, and finish state.
- Gameplay-critical values must never use existing tiny pixel-font canvas/page styles: lap, gate, speed, wrong-way, off-track, penalty, countdown, and finish copy must be at least 12px.
- Letter spacing is `0` in gameplay HUD/control text. Existing wider arcade heading spacing remains outside the active fullscreen route only.
- Display text is reserved for countdown/go/finish overlays. Do not use display sizing for HUD chips or analog control labels.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#06060d` | Fullscreen game background and canvas backing field |
| Secondary (30%) | `#0f0f1e` | HUD plates, analog well, compact status strip, non-card overlay surfaces |
| Accent (10%) | `#ffd700` | Active analog knob/vector, next checkpoint gate, start/finish marker, countdown/go value, focus ring, one primary HUD value |
| Destructive | `#ff3333` | Wrong-way warning after grace period, off-track penalty state, connection/error state |

Accent reserved for: active analog knob/vector, next checkpoint gate, start/finish marker, countdown/go value, current lap or next-gate HUD value, and keyboard focus ring. Do not apply accent to every track boundary, every HUD border, decorative glows, or inactive checkpoint gates.

Additional existing colors may be retained with fixed meanings: `#00aadd` for route direction arrows and secondary track guide lines, `#33ff66` for on-course/clean-lap positive state, and `#ddeeff` for readable primary text. Off-track warning may use amber/yellow for the grace period, but persistent penalty must switch to `#ff3333`.

Active HUD copy:
- Objective: `Complete 3 laps clockwise`
- Lap: `Lap 1/3`
- Checkpoint: `Gate 2/4`
- Direction: `Clockwise` or `Wrong way`
- Course state: `On course`, `Off track`, or `Penalty`

Copy rules:
- Keep active play copy terse. Do not show instructional paragraphs inside the active viewport.
- Use `Circle` or `Circle Track` as the mode label. Do not introduce `Figure Eight` copy in Phase 4.
- Error copy must pair a plain problem with one next action.

## Phase Interaction Contract

### Fullscreen Route

- Render the circular track in the Phase 1 fullscreen gameplay shell, not inside `.panel`, `.viewport`, `.card`, the normal top navigation chrome, or a lobby-style page section.
- Shell dimensions: `width: 100vw`, `min-height: 100dvh`, `overflow: hidden`, and route-level containment that prevents page scrolling.
- Landscape phone is the primary layout. Portrait must remain playable by stacking HUD top, track center, and analog control bottom without scrolling.
- Respect safe areas on all edges with `max(16px, env(safe-area-inset-*));`; keep extra bottom safe-area clearance around the analog pad.
- Canvas/track owns the main visual mass. HUD and controls overlay/dock around it and must not obscure the next checkpoint, player car, or start/finish gate.

### Track Visual Contract

- Use a simple circular or oval ring, not the existing complex `sprint-circuit` polyline.
- Render clear inner and outer boundaries with enough road width for forgiving phone steering.
- Default direction is clockwise and must be visible through route arrows, start/finish marking, and next-gate emphasis.
- Draw a subtle center guide line on the road surface; it is secondary guidance, not the lap validation mechanism.
- Draw one start/finish gate plus four ordered checkpoint gates around the circle. Inactive gates use secondary guide color; the next gate uses accent.
- Label gates tersely as `Start` and `1`, `2`, `3`, `4`. Labels must not collide with car sprites, HUD, or control zones.
- Off-track feedback: road boundary or car halo shifts to warning color during the grace period; persistent penalty state uses destructive color.
- Wrong-way feedback: route arrows or direction chip shift to warning color first; persistent wrong-way penalty uses destructive color.
- Do not render figure-eight crossing, intersection priority, crossing arrows, or overlapping-road behavior in Phase 4.

### Analog Control Contract

- Primary input is one bottom-left `AnalogPad` that outputs normalized `{ x, y, magnitude }`; magnitude controls throttle strength and release returns the car toward neutral/coasting.
- `x` and `y` are clamped to `-1..1`; `magnitude` is clamped to `0..1`.
- Use smooth input and turn damping visually: the car should not snap sharply when the thumb crosses center.
- The analog pad must show neutral, active-drag, disabled, and keyboard-focus states without layout shift.
- Touch surfaces must use Pointer Events with pointer capture where supported plus `touch-action: none`, `user-select: none`, and `-webkit-user-select: none`.
- Pointer up, pointer cancel, lost capture, blur, visibility change, route unmount, and disabled state must reset analog input to neutral.
- Right-side active gameplay buttons are not required for Phase 4. If an existing shell requires a right cluster, it may show a lower-priority brake/reset control only if the runtime supports it; it must not become the core skill loop.

### Keyboard And Desktop Fallback

- WASD and Arrow keys map to the same normalized analog vector as the touch pad.
- Diagonal keyboard input normalizes magnitude to `1` instead of exceeding analog range.
- Mouse drag on the analog pad remains supported for local testing.
- If optional action buttons are present, Space/Enter activate primary and Shift/Control activate secondary as defined in Phase 1.
- Keyboard focus order: analog pad, optional action/reset button, exit/back control if present. Focus ring uses `#ffd700` and remains visible over canvas and dark overlay surfaces.

### HUD Contract

- HUD is React-rendered text outside the canvas so tests and assistive tech can inspect it.
- Required fields: objective, lap, next checkpoint, direction, speed, course/penalty state, countdown/session state.
- Recommended compact layout in landscape: top strip with `Circle Track`, `Lap 1/3`, `Gate 2/4`, `42 km/h`, `On course`; direction/penalty chip may sit at top-right.
- Portrait layout: top strip wraps into two rows before reducing track size; it must not overlap the analog pad.
- Use `aria-live="polite"` for countdown, finish state, penalty changes, off-track transition, and wrong-way transition. Do not announce speed every tick.
- HUD state names must match server-authoritative snapshot data, not locally inferred progress.

### Results Contract

- Finish state overlay may use display typography for `Finished` and a compact summary below it.
- Results summary for Phase 4 must expose finish time, rank, lap count, and penalty count when available.
- Copy for mode summary: `Circle Track`, `Time`, `Laps`, `Penalties`.
- Results may reuse existing results page layout, but Phase 4 must provide enough summary fields for the page to explain why a smoother run won.

### Shared Contract Expectations

- Client emits compact analog input intents through `client:game-input`; final position, speed, lap, checkpoint, penalties, wrong-way state, off-track state, and finish state are server-authoritative.
- Snapshot fields must support phone HUD rendering: lap index/total, next checkpoint index/total, speed, analog/input echo if available, off-track warning, wrong-way warning, penalty count, and finish state.
- Do not build against stale race-specific socket events. Use `server:session-state`, `server:session-finished`, and `client:game-input`.
- Checkpoint/lap validation must use explicit gates. Do not rely only on nearest-point projection or raw angle progress for UI or runtime validation.
